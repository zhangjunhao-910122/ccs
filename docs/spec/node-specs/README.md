# 节点三件套与机器可读契约索引

本目录是 GitHub Issue #18（规格：节点三件套与机器可读契约）的交付物。每个节点一个目录，含三份规范文档与一份机器可读契约：

- `《节点执行规范》.md`：目标与职责、启动和输入、节点内执行顺序、必需输入与对应核验任务表、阻塞补件与退回执行、节点异常专门要求、本项结束。
- `《审核规则规范》.md`：共同审核判定规则 10 条、本节点专门规则（证据输入 / 核验方法 / 接受条件 / 不满足或待核处理 / 记录要求）、结论汇总约束。
- `《成果与完成交接规范》.md`：双成果内容责任、等待版·复核版·完成版·终止版四态、逐项完成核查表、确认与交接、文件版本与追溯。
- `assets/contract.json`：`schema_version` 1 的机器可读契约，含规则编号、来源 sha256、状态映射、人工授权与子步骤策略。

契约结构约束见 [`contract.schema.json`](contract.schema.json)。

## 全局口径

- 节点编号一律三位（`N01`~`N17`）；引用《判定规格》的审核类型写「类型N1」~「类型N6」，不得把类型编号当作节点编号。
- 节点状态 11 态：待执行 / 进行中 / 等待补件 / 整改中 / 等待现场核实 / 等待人员确认 / 等待机构结果 / 已具交接条件 / 已完成 / 不适用 / 终止。
- 判定四态：conform / nonconform / insufficient / na；事实四态：user_stated / material_supported / verified / conflict；成果四态：waiting / review / final / terminated。
- 原因码 13 个：BASIS_MISSING、BASIS_UNVERIFIABLE、BASIS_SUPERSEDED、APPLICABILITY_UNKNOWN、NA_WITHOUT_BASIS、EVIDENCE_MISSING、EVIDENCE_CONFLICT、EVIDENCE_UNREADABLE、SAMPLING_INSUFFICIENT、CLAUSE_NOT_IN_TREE、GAP_CONFIRMED、REPORT_ITEM_MISSING、DECISION_BLOCKED_OVERDUE。
- 数值一律不写死：人日、比例、间隔、抽样数量与验证时限引用 #21 计算结果（`tools/calculate.py`、`tools/calendar_ratio.py`、`tools/params.yaml`）或写「待核」。
- 照片不可取证的 4 类（文件内容完整性、访谈、时间序列类、数据真实性与完整性）在相关节点显式写明，缺失即落 `insufficient`。
- ISO 条款号只取 `audit-point-library/clause_trees/*.yaml` 中实有条号；CNCA 条款用 5.x 现行编号（QMS:2025 版 / EMS:2026 版 / OHSMS:2026 版）。
- 产物命名：`<任务标识>_<节点编号>_<成果名称>_<版本>.<扩展名>`，状态后缀 `-waiting` / `-review` / `-final` / `-terminated`。
