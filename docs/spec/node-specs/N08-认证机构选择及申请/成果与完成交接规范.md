# N08 认证机构选择及申请 — 成果与完成交接规范

> 本规范与《N08 节点执行规范》《N08 审核规则规范》及 `assets/contract.json` 同属节点 N08 的规范三件套。

## 1. 双成果内容与责任

每个节点产出正式文件与一页以内简报两件。正式文件落 `02_成果/<节点>/`（过程底稿落 `01_工作稿/`），简报落 `03_简报/<节点>/`；索引落 `04_索引/index.json`。`00_原始材料/` 只读。

| 成果 | 文件基名 | 扩展名 | 目录 | 内容与格式依据 |
|---|---|---|---|---|
| 过程底稿 | <任务标识>_<节点编号>_过程底稿 | .json | 01_工作稿/（底稿为唯一事实源，正式件由底稿投影） | S4 §7 JSON 底稿是唯一事实源，含 schema_version、artifact、anchors、judgements、nonconformities、report_refs；其余正式文件由底稿投影生成。 |
| 预览 | <任务标识>_<节点编号>_预览 | .md | 03_简报/<节点>/ | S4 §8.2 一页以内简报：成果态、版本、判定四态计数、已确认不符合项、未解决问题清单、待签事项、正式文件清单与 sha256、下一步。 |

### 1.1 内容责任分工

- 过程底稿（JSON）是唯一事实源，含 `schema_version`、`artifact`、`anchors`、`judgements`、`nonconformities`、`report_refs`；其余正式文件全部由底稿投影生成，同底稿两次生成字节级一致。
- 简报（预览）必含：成果态、版本、判定四态计数、已确认不符合项（编号/条款号/类别/整改时限引 #21 计算结果）、未解决问题清单（条款号+原因码+待办动作+责任角色）、待签事项、正式文件清单+sha256、下一步。
- 工具只生成待签版本：签字栏留空标「（待签）」，第 19 项写「（待填写）」，不代签不伪造签章；签署栏为空的产物只能是 `waiting` 或 `review`。
- 五件配套必须同版：版本号与状态后缀一致，缺一件不得转「已具交接条件」，不得标 `final`。

## 2. 成果四态与节点状态对齐

| 节点状态 | 成果态 | 文件后缀 |
|---|---|---|
| 进行中 | waiting | -waiting |
| 等待补件 / 整改中 / 等待现场核实 / 等待人员确认 | waiting | -waiting |
| 已具交接条件 | review | -review |
| 复核退回 | waiting | -waiting（版本号递增，旧版保留） |
| 已完成 | final | -final |
| 终止 | terminated | -terminated |

禁止流转：`waiting` 直跳 `final`；`final` 改写；`review` 覆盖同名文件。已存在同名文件时拒绝写入，不静默覆盖。

## 3. 逐项完成核查表

| 检查项 | 完成条件 | 通过证据要求 | 初始状态 |
|---|---|---|---|
| N08-C01 | 机构选择记录核对完成 | 选择记录可定位 | 未执行 |
| N08-C02 | 提交清单核对完成 | 缺失与不可读件已登记 | 未执行 |
| N08-C03 | 申请书签署与授权核对完成 | 核对记录有结论 | 未执行 |
| N08-C04 | 合同事项齐备性核对完成 | 合同核对表逐项有结论 | 未执行 |
| N08-C05 | 合同签署与生效核对完成 | 状态记录显示已满足生效条件 | 未执行 |
| N08-C06 | 关键标识登记完成 | 标识原值与来源一致 | 未执行 |

转「已具交接条件」的机器可判定前置条件：

1. 上表逐项全部为「已执行」且有通过证据；
2. 全部规则均已判定，无未判定检查项；
3. 无未结等待态（如有须作为已登记未决事项显式列出，并带责任人与期望回复）；
4. 若产出判定，锚点表已存在且每个结论可回指锚点与依据，依据 `unverifiable` 只能 `insufficient`；
5. 数值类结论均引自 #21 计算结果，且 `source_ref` 与核验状态齐备；
6. 本节点承载的人工闸口已放行（无）。

## 4. 确认与交接

### 4.1 交接三件套

1. 产物：正式文件与简报，含文件名、版本、成果态与 sha256。
2. 机器可读契约摘要：`assets/contract.json` 关键字段快照，含规则编号、来源 sha256、状态。
3. 未决事项清单：缺件、冲突、待人工确认、待核数值，逐条带责任人与期望回复。

### 4.2 交接记录字段（只追加不修改）

`handoff_id`、`task_id` / `node_id`、`from_state` / `to_state`、`artifacts`（文件名+sha256+四态）、`contract_digest`、`open_items`、`numeric_refs`、`actor` / `confirmed_by`、`timestamp`。

### 4.3 交接前的签署与独立性边界

| 角色 | 授权事项 | 依据 |
|---|---|---|
| 委托人 | 认证机构选择与申请提交 | S3 §2.1 N08 |
| 委托人授权代表 | 申请书与合同签署 | S3 §11.2 签署边界 |

## 5. 文件版本与追溯

- 命名：`<任务标识>_<节点编号>_<成果名称>_<版本>.<扩展名>`；成果名称为基名加状态后缀（`-waiting` / `-review` / `-final` / `-terminated`），版本为 `v1`、`v2`，节点内单调递增不复用。
- 示例：`TASK-2026-QMS-A_N08_审查表-waiting_v1.xlsx`。
- 索引 `04_索引/index.json` 字段：`file_name`、`artifact_base`、`node_id`、`artifact_state`、`version`、`sha256`、`created_at`、`superseded_by`、`review_history`、`signed_by`。
- 同节点同版本五件 sha256 成套，缺件不得标 `final`；已被新版替代的原文件不改其状态，索引置 `superseded_by`。
