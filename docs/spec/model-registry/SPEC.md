# 模型注册表与训练推理流水线规格（可切换模型 + 样本外区间口径）

- 票：[实现：可切换模型注册表与机器学习训练、推理流水线](https://github.com/zhangjunhao-910122/ccs/issues/48)（#48，父地图 #22）
- 版本：v1.0（2026-11-07）
- 上游：[实现：朴素基线与滚动回测框架](https://github.com/zhangjunhao-910122/ccs/issues/31)（#31）、[规格：组合负荷预测特征与口径（含防穿越）](../load-forecast/SPEC.md)（#45）、[实现：回测报告产物与达标判定](https://github.com/zhangjunhao-910122/ccs/issues/37)（#37）
- 可执行产物：`reference_model_pipeline.py`（参考实现 + E1–E12 自检）、`model.config.json`（口径配置）、`model_artifact.schema.json`（注册表与产物数据模型）、`verification.txt`（自检输出）、`samples/` + `out/`（回测产物）

## 1. 问题与目的

「模型」在本项目里不是一段脚本，而是一个**要能登记、能切换、能复现、能被下游引用**的对象。这四件事各自都会出错：

1. **登记**：模型版本、特征集、超参、训练窗口、指标、产物摘要若不落成可查询的结构，下游只能靠口头知道「存在一个 GBDT」。
2. **切换**：模型若在上层代码里写死分支，加一个模型就要改上层调用，切换成本随模型数线性增长。
3. **复现**：固定种子不足以复现——数据版本、预处理口径、特征集三者任一变化，产物即变。
4. **区间**：点预测之外的区间是调度与结算的直接依据；区间口径若取自训练窗内的拟合残差，对可拟合模型系统性偏窄，覆盖不足而无人察觉。

本规格把这四件事定死，并给出可执行参考实现：

- 训练目标用**残差口径**（相对主基线 N3 的残差），不用绝对值；
- 区间用**样本外交叉拟合 + 时段尺度 + 日型分组**校准，名义 90% 对应 P5/P95；
- 模型通过配置接入，**加模型不改上层调用**；
- 固定 seed + 固定数据版本 → 同一 `artifact_digest`。

本期只做**口径与参考实现**，不锁定精度阈值（阈值由 #37 在真实数据上写死，地图 #22 Q28 已定「先建历史基准再定线」）。

## 2. 第一性原理

1. **预测的对象是「相对基线的增量」，不是绝对负荷。** 同一条曲线在不同时段的绝对水平差一个量级，全局绝对值模型无法表达这种水平，只能把时段结构记进特征里硬拟合。实测（早期口径）：绝对值目标下 GBDT / 分位数模型的 MAE 劣化到基线的 4 倍；改成相对 N3 的残差后，全部候选模型均优于基线。
2. **区间宽度只能来自样本外误差。** 若区间宽度取自训练窗内的拟合残差，则模型拟合得越好、区间越窄——这是把「训练内乐观」直接写进风险提示。实测：样本内口径下可拟合模型的工作日层实测覆盖率只有 0.71–0.87，而朴素模型（无拟合参数）反而最接近名义值。
3. **名义覆盖率与分位必须自洽。** 名义 90% 的双侧区间是 P5/P95；用 P10/P90 只能覆盖 80%，是口径硬错误（本票已修）。
4. **误差随时段变化，区间宽度就必须随时段变化。** 实测基线残差标准差凌晨 0.14 → 午间 0.49（约 3.5 倍）；固定宽度的区间必然在午间失效。做法：按该时段基线残差的 MAD 缩放。
5. **尺度必须样本外。** 分母若取自训练窗内模型自身残差，就是把样本内乐观重新引入。基线 N3 无拟合参数，其残差 MAD 天然是样本外量，可作尺度。
6. **校准样本要贴近评估期。** 时间向前交叉拟合（forward-chaining）保证每个校准样本都是「用更早数据训练出的模型对后续数据的预测」；但远端折的误差水平可能已经过期，故只取最近若干块估分位。
7. **日型是残差分布的一等公民。** 工作日、休息日、法定节假日的残差分布不同（实测节假日层基线 MAE 是工作日的 4.4 倍）。区间按日型分组；训练窗内没有同类日样本时，如实标注「不支持」，不假装能覆盖。
8. **可复现 = 固定 seed + 固定数据版本 + 固定特征集。** 三者写入产物（`seed` / `data_digest` / `feature_set_hash`），同三者必然同 `artifact_digest`。
9. **注册表只追加。** 模型与预测记录一旦发出不可原地改；否则回测与审计会同时失效。
10. **加模型不改上层调用。** 模型通过配置枚举接入；注册表与推理按配置遍历。上层只认「配置里有哪些模型」，不认「代码里写了哪些分支」。

## 3. 决策（L1–L14）

- **L1 模型对象与版本键。** 键 = `(model_id, version)`；`version` 与 `feature_set_hash` 绑定，**特征集变更必须升版本**（沿用 #45 L3 的规则），不得复用旧版本号。
- **L2 训练目标 = 相对 N3 的残差。** `train.target = RESIDUAL_ON_N3`；标签 `y = 真实值 − 同一切点的 N3 基线`，预测值加回 N3 才是绝对预测。理由见 §2.1。
- **L3 模型族是候选，不是默认。** `NAIVE`（等于基线本身，作为参照）、`LINEAR`（岭回归）、`GBDT`（梯度提升树）、`QUANTILE`（分位数线性）、`SEQUENTIAL`（AR(1) 残差自回归）。本期不锁定任何族为默认，默认选择由 #37 在真实数据上定；配置里 `selection.default_by_origin` 只是参考实现中的占位。
- **L4 训练窗与预处理。** `train.window_days = 28`（目标日之前可得日往前 28 个有数据日）；可得日由 `available_at <= origin` 反推；标准化器只在训练窗 fit；缺失显式，不插值不补零。
- **L5 区间分位与名义覆盖率自洽。** `interval.quantiles = [0.05, 0.5, 0.95]`，`nominal_coverage = 0.9`，`alpha = (1 - nominal) / 2`。分位与名义值不自洽即自检失败（E9）。
- **L6 区间校准层：forward-chaining + 近端块 + 日型分组 + 时段尺度。** 校准流程：
  1. 训练窗按时间切 `calibration_folds = 4` 块；第 k 折的校准样本 = 第 k 块，训练集 = 第 1..k−1 块（严格只用更早数据，不穿越）；
  2. 每折的误差 `err = 真值残差 − 模型残差`，分数 `score = err / 该时段基线残差 MAD`；
  3. 只用**最近 `calibration_recent_blocks = 2` 块**的样本估分位与位移（远端折的误差水平已过期）；
  4. 分位前对分数做 `winsorize_percentile = 2.0` 的极值裁剪（早期折样本少，误差可能极端）；
  5. 分位按**日型组**分别估计（`day_groups` 配置驱动），组内样本不足 20 行回退全局；
  6. 区间 = 点预测 + `shift`（误差中位数）+ 分位 × 该时段尺度，并夹紧 `p10 <= p50 <= p90`。
  **点预测不平移**：校准只修区间，不改模型语义（朴素基线的点预测就是 N3 本身，平移它会直接损害点误差）。
- **L7 尺度 = 基线残差 MAD。** `MAD = 1.4826 × median(|x − median(x)|)`，按 24 个时段分别估计，每时段样本不足 8 行回退全局尺度。选基线尺度而非模型尺度，是因为基线无拟合参数，其残差分布是样本外的。
- **L8 日型分组与「支持度」。** `day_groups`：`WORKDAY = 普通工作日 + 调休上班日`、`RESTDAY = 普通休息日`、`HOLIDAY = 法定节假日`。训练窗内某日型的可得天数 < `min_support_days = 3` 时，该日型的实测覆盖率**只报告不判定**，标 `UNSUPPORTED_DAYTYPE`——这是数据约束，不是实现缺陷。
- **L9 指标与分层。** MAE / RMSE / nMAE；按起点（`P_CURVE` / `P_BID` / `P_REVIEW`）、用户、日型分层；三个起点分别计算，不得混算。**阈值不预填**。
- **L10 注册表只追加。** `model_registry` 每行含 `model_id`、`version`、`scope`、`metrics`、`seed`、`data_label`、`data_digest`、`artifact_digest`、`feature_set_hash`、`supported_origins`、`code_version`、`build`。`artifact_digest` 是产物内容的摘要，`data_digest` 是输入数据版本摘要，二者必须同时入表，否则无法解释产物为何变化。
- **L11 产物落盘。** `out/` 下：`model_registry.jsonl`（注册表）、`forecast_runs.jsonl`（运行头）、`forecast_predictions.jsonl`（预测记录）、`model_summary.json`（汇总）、`backtest_error_table.csv`（切点×模型×用户×起点×时段的误差表）、`model_period_summary.csv`、`artifacts/`（每个模型产物）。**点级明细不落盘**（避免把海量明细写进仓），只落聚合与摘要。
- **L12 可复现。** 固定 `seed` + 固定 `data_digest` + 同一特征集 → 同 `artifact_digest`（E10 断言两次训练 digest 相同）。
- **L13 上游 schema 只做加法式扩展。** `docs/spec/load-forecast/forecast.schema.json` 的 `model_registry` 表**新增** 10 个字段（`scope` / `metrics` / `seed` / `data_label` / `data_digest` / `artifact_digest` / `supported_origins` / `code_version` / `build`，均 `required: false`），并给 `MODEL_FAMILY` 枚举增 `SEQUENTIAL`、新增 `MODEL_SCOPE` 枚举；不改动 #45 已发布的任何既有字段与约束，避免下游破坏。
- **L14 达标线归 #37。** 覆盖率与精度都是**经验量**，受数据分布支配；本票负责口径正确性与实测记录，达标线由 #37 在 12 个月真实数据上写死（地图 #22 Q28「不预填」）。因此自检判定的是**口径是否自洽**，覆盖率偏差按日型分层如实记录并在规格里写明原因。

## 4. 模型与配置口径

| 模型 | 族 | 特征 | 超参 | 角色 |
|---|---|---|---|---|
| `naive_n3/v1` | NAIVE | `f_load_med_weekday8` | — | 参照（点预测 = N3） |
| `linear_v1/v1` | LINEAR | 6 条负荷/日历特征 | ridge 0.001 | 候选 |
| `gbdt_v1/v1` | GBDT | 同上 | 30 棵 / lr 0.1 / depth 3 / leaf 20 | 候选 |
| `quantile_v1/v1` | QUANTILE | 同上 | 3 分位 / 80 iter / lr 0.05 / warm start | 候选 |
| `ar_resid_v1/v1` | SEQUENTIAL | AR(1) 残差自回归 | min_pairs 5 | 候选 |

- 特征集哈希由**实际使用的特征子集**重算并入产物；改变特征集必须升版本（L1）。
- 超参一律写在 `model.config.json`，不写进代码（加模型只改配置）。

## 5. 区间口径为什么这么定

| 做法 | 后果 | 本票选择 |
|---|---|---|
| 区间取训练窗内拟合残差 | 可拟合模型区间系统性偏窄（实测工作日层覆盖 0.71–0.87） | ❌ |
| 单次留出（尾部 30%）校准 | 校准样本仅 11 天 × 24 时段，分位噪声大（实测切点间覆盖在 0.13–1.0 跳） | ❌ |
| 校准时标准化器在留出段 fit | 泄漏 + 分布错配，实测比样本内口径更差 | ❌ |
| 名义 90% 用 P10/P90 | 实际只覆盖 80% | ❌（改 P5/P95） |
| 归一化分数 ÷ 基线残差 MAD | 时段自适应，且分母天然样本外 | ✅ |
| 日型分组 | 假期/工作日残差分布不同，分组后各组各自标定 | ✅ |
| 只用最近 2 块估分位 | 远端折误差水平已过期 | ✅ |
| 点预测随校准平移 | 朴素基线的点预测就是 N3，平移即损害点误差 | ❌（不平移） |

## 6. 实测对比（合成数据，5 个月）

> 回测口径与 #31 完全一致：同窗同起点，逐时点对齐。基线表 digest `37938619cc84741f…` 与 #31 已发布值逐格一致（E5 硬证据）；本期合并表 digest `0648de63…`（区间口径变更后重算，与上期 `da3995c1…` 不同属预期）。
> 样本：28 个切点 × 3 用户 × 3 起点，`P_CURVE/ALL` 层 2006 个评分点。

### 6.1 点精度（MAE，越小越好）

| 模型 | `P_CURVE` | 相对 N3 | `P_BID` / `P_REVIEW` | 相对 N3 |
|---|---|---|---|---|
| N3 基线 | 0.367747 | — | 0.367747 | — |
| `naive_n3` | 0.367747 | 0.0% | 0.367747 | 0.0% |
| `linear_v1` | 0.314181 | 14.6% | 0.273528 | 25.6% |
| `gbdt_v1` | 0.332699 | 9.5% | 0.329993 | 10.3% |
| `quantile_v1` | **0.290133** | **21.1%** | **0.246542** | **33.0%** |
| `ar_resid_v1` | 0.328690 | 10.6% | 0.309506 | 15.8% |

结论：五个候选族**全部不劣于 N3 基线**（`naive_n3` 按定义等于基线）；残差口径下最优为 `quantile_v1`。默认族仍不锁定（L3），由 #37 在真实数据上定。

### 6.2 区间覆盖率（PICP，名义 0.9；`P_CURVE` 层）

| 模型 | ALL | 普通工作日 | 普通休息日 | 法定节假日 | 调休上班日 |
|---|---|---|---|---|---|
| `naive_n3` | 0.886 | 0.929 | 0.811 | 0.972 | 0.028 |
| `linear_v1` | 0.691 | 0.818 | 0.706 | 0.470 | 0.250 |
| `gbdt_v1` | 0.735 | 0.738 | 0.600 | 0.933 | 0.000 |
| `quantile_v1` | 0.695 | 0.835 | 0.639 | 0.510 | 0.167 |
| `ar_resid_v1` | 0.665 | 0.605 | 0.586 | 0.948 | 0.000 |

**这张表是本票最重要的产出，也是最反直觉的一张**：点精度最好的 `quantile_v1` 区间覆盖最差，而几乎不做学习的 `naive_n3` 覆盖最好。原因不是校准写错了，而是**区间宽度必须由误差水平决定，模型越依赖训练窗学到的模式，外推期的误差水平越高于训练窗，区间就越难覆盖**：

- `naive_n3` 的点预测就是基线本身，其误差水平不随「学到的模式」过期 → 区间（按基线残差尺度标定）覆盖最好；
- 可拟合模型在训练窗拟合得好，交叉拟合后的残差仍系统性小于评估期真实残差（评估期叠加了分布漂移），区间因此偏窄。

调休上班日层（72 点）全部模型覆盖崩溃（0.00–0.25），原因见 §7.1。

**因此本票不预填覆盖率达标线**：名义 90% 是口径目标，达标线归 #37 在 12 个月真实数据上写死（L14、地图 #22 Q28）。当前阶段可以确定的是——**可拟合模型的区间尚不足以对外承诺**，这是真实数据复核前必须解决的第一位问题。

## 7. 已知失效边界

1. **法定节假日与调休上班日：区间不可用。** 28 天训练窗内没有「历史同期假期」样本（长假一年只有几次），假期切点的残差分布相对训练窗整体漂移约 0.86（训练窗残差中位数 −0.06 vs 评估期 −0.92），任何只用历史窗口的校准都无法覆盖。实测：调休上班日层全部模型覆盖 0.00–0.25。**这是数据量约束，不是实现缺陷**；真实数据（12 个月+）把训练窗拉到年尺度后才有同类日支撑。届时按 §3 L8 的日型分组自然生效，本规格的口径不需要改。
2. **分布漂移期的可拟合模型覆盖率不足。** 当训练窗含长假而评估期是普通工作日时，模型相对基线的增益会「过期」，实测可拟合模型在工作日层的实测覆盖率只有 0.60–0.84（名义 0.9），而 `naive_n3` 达 0.92–0.97（§6.2）。处理方式：如实记录，不在本票预填达标线（#37 在真实数据上复核）；**真实数据到位后第一件要重测的就是这一项**。
3. **远端块误差水平过期。** 只用最近 2 块估分位是折中：块数更多更稳但更过期，块数更少更贴近但噪声大。
4. **合成数据标签。** 本期产物 `data_label = SAMPLE-SYNTHETIC`，按 `model_artifact.schema.json` 的不变量，**不得用于达标判定**，只用于口径与管线验证。

## 8. 数据模型（`model_artifact.schema.json`）

| 表 | 键 | 关键字段 |
|---|---|---|
| `model_registry_record` | `(model_id, version)` | scope / metrics / seed / data_label / data_digest / artifact_digest / supported_origins / code_version / build |
| `model_artifact` | `(model_id, version, user_id, origin_type, target_date)` | feature_ids / target / scaler / params / calibration / training_window / train_metrics / artifact_digest |

不变量（schema 内 `invariants` 段）：注册表只追加；`feature_set_hash` 必须与实际特征子集重算一致；校准参数只能在训练窗内 fit；同 seed + 同 data_digest → 同 artifact_digest；`p10 <= p50 <= p90`；残差口径理由必填；`data_label = SAMPLE-SYNTHETIC` 的产物不得用于达标判定。
